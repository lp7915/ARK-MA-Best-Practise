# AC-06 回执保存

- **ID / 版本**：AC-06 / 1.0.0
- **粒度**：原子能力
- **归属注意力**：中台（存储、权限、计量、审计）＋ 研发（可检索性）

---

## 1. 职责

把一条或多条标准回执（及可选产物）持久化到可检索的存储，分配 `receipt_id`，
写入索引并返回定位信息。它是整条链路「调用可追溯」的**汇聚点与唯一落盘出口**。

**不做**：不产生业务数据、不改写回执内容（只补 `receipt_id` 与存储元信息）、不做分析。

---

## 2. 输入契约

### 2.1 回执列表 `receipts`
标准回执数组（见规范 §5）。每条应已由上游能力填好除 `receipt_id` 外的字段。

### 2.2 产物列表 `artifacts`（可选）
```json
[ { "from_capability": "AC-05", "format": "png|svg|html|vega|json",
    "content_ref": "AC-05 等产出的临时句柄/内联内容", "filename_hint": "" } ]
```

### 2.3 存储目标 `target`
```json
{
  "backend": "fs | lark_drive | oss",
  "index_key": "归档归属键，如 topic_id/run_id",
  "retention_days": null
}
```
- `backend` 候选见 §9 未决项，默认 `fs`（本地文件，便于设计期验证）。

---

## 3. 参数 `params`

| 参数 | 取值 | 默认 | 说明 |
|------|------|------|------|
| `mode` | `append` / `overwrite` | `append` | 同 `index_key` 下是追加还是覆盖 |
| `with_bundle` | bool | `false` | 是否把本次回执+产物打成一个可下载归档包 |
| `redact` | string[] | `[]` | 落盘前需脱敏的回执字段路径（如含敏感参数） |

> `redact` 对齐 CLAUDE.md / 共享库规则：凭据、token 等不得以明文落盘。

---

## 4. 输出契约

```json
{
  "stored": [
    { "receipt_id": "分配的唯一id", "capability_id": "", "location": "存储定位",
      "backend": "", "stored_at": "ISO8601" } ],
  "artifacts_stored": [
    { "from_capability": "", "location": "", "bytes": 0 } ],
  "index_entry": {
    "index_key": "", "receipt_count": 0, "artifact_count": 0,
    "bundle_location": null }
}
```
- `receipt_id` 生成规则需保证全局唯一且可排序（建议时间前缀 + 随机后缀）。
- `index_entry` 让同一 `index_key`（一次报告生产 run）下的全部回执可被一键检出。

**回执 `deltas`**：`{ "stored": 回执数, "artifacts": 产物数, "backend": "" }`，
`status`：全部写入 `success`；部分写入成功 `partial`；存储目标不可达/无权限 `failed`。

> 注意：AC-06 自身这次调用也会产生一条回执；为避免递归落盘，AC-06 的自身回执默认随本次结果
> 返回但**不再二次保存**（除非显式再调一次）。

---

## 5. 错误与边界

| 情况 | 处理 | status |
|------|------|--------|
| backend 不可达/鉴权失败 | 中止，不产生半写入 | failed |
| 部分回执写入成功、部分失败 | 返回已写入项并标注失败项 | partial |
| `overwrite` 命中已有 `index_key` | 按参数覆盖 | success |
| `redact` 字段不存在 | 跳过该脱敏项并告警 | partial |
| 产物 `content_ref` 已失效 | 跳过该产物并记录 | partial |

不负责：业务数据建模、权限策略定义（权限由中台在 backend 层治理，本能力只按身份调用）。

---

## 6. 幂等与确定性

- 非纯函数（有副作用：写存储）。
- `mode=overwrite` + 固定 `index_key` ⇒ 可重入，重复调用收敛到同一归档状态。
- `mode=append` 下重复调用会产生新 `receipt_id`；若需去重由上层传稳定 `index_key` + overwrite。

---

## 7. 复用场景

- **所有组合模块与 Topic 的终点**：汇集全链路回执，形成一次 run 的完整调用证据。
- 费用/权限审计（中台）：按 `index_key` 回溯一次生产用了哪些能力、处理了多少数据。
- 复盘与版本迭代：对照历史回执看口径/参数变化。

---

## 8. 验收标准

- [ ] 多条回执一次写入后，各自获得唯一且可排序的 `receipt_id`。
- [ ] 按 `index_key` 能检出同一 run 的全部回执与产物。
- [ ] `redact` 指定字段落盘后为脱敏态，原文不出现在存储中。
- [ ] backend 不可达时判 `failed` 且无半写入残留。
- [ ] `overwrite` 重复调用收敛到同一归档状态（可重入）。
- [ ] `with_bundle` 产出的归档包可下载且含全部回执+产物。

---

## 9. 未决项（评审时与中台确认）

1. `backend` 候选优先级：`fs`（设计期）→ `lark_drive`（交付期，走飞书应用身份）→ `oss`（规模化）。
2. `retention_days` 默认值与合规保留要求。
3. `index_key` 与 ADA「项目标识/run_id」的对应关系——需对齐项目管理层的归属设计。
4. 回执存储的权限与计量口径，与五个执行入口的计费如何串联。
