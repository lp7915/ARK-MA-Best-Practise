# AC-01 字段校验

- **ID / 版本**：AC-01 / 1.0.0
- **粒度**：原子能力
- **归属注意力**：数据（口径质量）＋ 分析师（规则定义）

---

## 1. 职责

按一份显式的校验规则集，逐行检查数据集，把数据**分流**为「有效行」与「无效行」，
并对每条无效行标注失败原因。

**不做**：不去重（交 AC-02）、不计算派生值（交 AC-03）、不修改原始值。
> 可选的「规范化」（trim/大小写归一）只在显式开启时执行，且作为独立标注输出，不静默改值。

---

## 2. 输入契约

### 2.1 数据集
标准信封（见规范 §4）。校验按 `schema.type` 判断类型，不猜测。

### 2.2 校验规则集 `rules`
```json
{
  "field_rules": [
    { "field": "字段名",
      "required": true,
      "type": "string|integer|number|boolean|datetime|enum",
      "min": null, "max": null,
      "min_len": null, "max_len": null,
      "regex": null,
      "enum": null,
      "desc": "该规则的业务含义" }
  ],
  "cross_field_rules": [
    { "name": "规则名", "expr": "字段A <= 字段B", "desc": "跨字段约束含义" }
  ]
}
```
- 规则里引用的字段必须存在于 `schema`，否则整次调用判 `failed`（规则与数据不匹配）。
- `type` 校验以规则为准；规则未声明的字段不校验类型。

---

## 3. 参数 `params`

| 参数 | 取值 | 默认 | 说明 |
|------|------|------|------|
| `on_error` | `reject_row` / `annotate_only` | `reject_row` | 失败行是进入 invalid 分流，还是全部保留只打标注 |
| `strict_schema` | bool | `false` | 为真时，数据中出现 schema 未声明字段即判失败 |
| `normalize` | bool | `false` | 是否执行 trim/大小写归一（结果写入 `normalized` 标注） |
| `stop_on_count` | int / null | `null` | 无效行超过该数即中止并判 `failed`（用于早停保护） |

规则（是什么）与参数（怎么处理失败）分离：换数据不改参数，换策略不改规则。

---

## 4. 输出契约

```json
{
  "valid_rows":   { "schema": [...], "rows": [...], "meta": {...} },
  "invalid_rows": { "schema": [...],
                    "rows": [ { "...原字段": "值",
                               "_errors": [ { "field": "", "rule": "", "msg": "" } ] } ] },
  "summary": {
    "total": 0, "valid": 0, "invalid": 0,
    "by_rule": { "规则名": 失败计数 }
  }
}
```
- `invalid_rows` 每行追加 `_errors` 数组，定位到字段与命中的规则。
- `annotate_only` 模式下 `valid_rows` 含全部行，失败行同样带 `_errors`。

**回执 `deltas`**：`{ "invalid": 无效行数, "by_rule": {...} }`，`status`：全通过 `success`、
部分失败 `partial`、规则/数据不匹配或触发早停 `failed`。

---

## 5. 错误与边界

| 情况 | 处理 | status |
|------|------|--------|
| 个别行违反规则 | 分流到 invalid 并标注 | partial |
| 规则引用了 schema 不存在的字段 | 整次中止 | failed |
| `cross_field_rules` 表达式无法解析 | 整次中止 | failed |
| 触发 `stop_on_count` | 中止，保留已处理结果 | failed |
| 全部通过 | 正常 | success |

不负责：缺失值填充、类型强转落库、重复识别。

---

## 6. 幂等与确定性

纯函数：同一数据集 + 同一规则集 + 同一参数 ⇒ 同一分流结果与摘要。无副作用、无落盘。

---

## 7. 复用场景

- **CM-01 数据准备组合**第二步（合并后、去重前的质量闸）。
- **CM-02 内容标注组合**：校验 LLM 标注结果是否落在 enum/格式约束内。
- 跨 Topic：任何取数/标注结果入库前的统一质量闸。

---

## 8. 验收标准

- [ ] 对含必填缺失、类型错误、越界、正则不匹配、枚举外值的样例，各自被正确归入 invalid 并标注命中规则。
- [ ] `annotate_only` 下不丢行且失败行带 `_errors`。
- [ ] 规则引用不存在字段时判 `failed` 且不产出半成品分流。
- [ ] `normalize` 关闭时输出值与输入逐字节一致（不静默改值）。
- [ ] 回执 `deltas.invalid` 与 `summary.invalid` 一致。
