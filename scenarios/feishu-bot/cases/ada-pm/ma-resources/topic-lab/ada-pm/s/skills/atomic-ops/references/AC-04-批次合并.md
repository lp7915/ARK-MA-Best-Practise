# AC-04 批次合并

- **ID / 版本**：AC-04 / 1.0.0
- **粒度**：原子能力
- **归属注意力**：数据（来源边界与溯源）＋ 研发（schema 对齐）

---

## 1. 职责

把多批数据集合并为一个数据集，对齐各批 schema、协调字段冲突，并为每行保留**批次溯源**，
产出合并后数据集 + schema 协调报告 + 冲突日志。

**不做**：不做去重（可选委托 AC-02，见 §3）、不校验合法性（交 AC-01）、不计算指标（交 AC-03）。

---

## 2. 输入契约

### 2.1 批次列表 `batches`
```json
[
  { "batch_id": "批次标识（如来源入口+时间）",
    "dataset": { "schema": [...], "rows": [...], "meta": {...} } }
]
```
- 至少 1 批；每批是一个标准信封。
- `batch_id` 全列表唯一，用于溯源列取值。

### 2.2 合并规则 `rules`
```json
{
  "schema_align": "union | intersection",
  "field_map": { "本批字段名": "统一字段名" },
  "type_conflict": "to_string | prefer_first | fail",
  "provenance_field": "_batch"
}
```
- `schema_align=union`：取字段并集，缺失字段补 null；`intersection`：仅保留各批共有字段。
- `field_map` 处理同义异名字段（如 `uid`↔`user_id`）向统一名归并。
- `type_conflict`：同名字段跨批类型不一致时的处理。

---

## 3. 参数 `params`

| 参数 | 取值 | 默认 | 说明 |
|------|------|------|------|
| `dedup_on_merge` | bool | `false` | 为真时合并后内联调用 `AC-02@1.x`（规则由 `dedup_rules` 给出） |
| `dedup_rules` | object / null | `null` | 透传给 AC-02 的去重规则 |
| `keep_batch_meta` | bool | `true` | 是否在 `meta.provenance` 汇总各批 meta |

> `dedup_on_merge` 是刻意保留的编排便利；若关闭，去重由上层组合模块显式接 AC-02，职责更清晰。

---

## 4. 输出契约

```json
{
  "merged": {
    "schema": [...统一后字段, {"name":"_batch","type":"string","desc":"批次溯源"} ],
    "rows": [ { "统一字段": "值", "_batch": "batch_id" } ],
    "meta": { "row_count": 0, "provenance": [ {各批 batch_id 与行数} ] }
  },
  "schema_report": {
    "mode": "union|intersection",
    "unified_fields": ["..."],
    "added_as_null": { "batch_id": ["该批缺失、被补 null 的字段"] },
    "dropped_fields": ["intersection 下被丢弃的非共有字段"]
  },
  "conflict_log": [
    { "field": "", "batches": ["b1","b2"], "types": ["integer","string"],
      "resolution": "to_string", "affected_rows": 0 } ]
}
```

**回执 `deltas`**：`{ "batches": 批数, "input_rows": 各批合计, "merged": 合并后行数,
"conflicts": 冲突字段数, "removed_by_dedup": 若开启去重的移除数 }`，
`status`：正常 `success`；`type_conflict=fail` 命中或字段映射无效 `failed`；
`intersection` 丢弃字段/补 null 发生 `partial`。

---

## 5. 错误与边界

| 情况 | 处理 | status |
|------|------|--------|
| 仅 1 批 | 直通并打溯源列 | success |
| 同名字段类型冲突且 `type_conflict=fail` | 中止 | failed |
| `field_map` 目标名与已有字段碰撞 | 中止 | failed |
| `batch_id` 不唯一 | 中止 | failed |
| intersection 后无共有字段 | 中止 | failed |
| 补 null / 丢字段发生 | 完成并记入报告 | partial |

不负责：主键重映射的业务判断、跨批口径统一（口径交 AC-03）。

---

## 6. 幂等与确定性

- 合并顺序 = `batches` 列表顺序；`merged.rows` 按批次顺序、批内行序拼接，确定可复现。
- 开启 `dedup_on_merge` 时确定性继承 AC-02 的确定性约束。

---

## 7. 复用场景

- **CM-01 数据准备组合**第一步（多次取数/多页结果合并）。
- 海外社媒舆情 Topic：多平台、多关键词批次汇总。
- 热点数据 Topic：按周次多次爬取结果合并。

---

## 8. 验收标准

- [ ] union 模式下缺失字段补 null，并在 `schema_report.added_as_null` 记录。
- [ ] intersection 模式下仅保留共有字段，丢弃项记入报告。
- [ ] 每行带正确 `_batch` 溯源，`provenance` 行数合计 = merged 行数。
- [ ] `field_map` 把异名同义字段正确归并。
- [ ] 类型冲突按 `type_conflict` 策略处理并记入 `conflict_log`。
- [ ] 开启 `dedup_on_merge` 时 `removed_by_dedup` 与内部 AC-02 回执一致。
