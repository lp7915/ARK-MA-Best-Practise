# AC-02 按规则去重

- **ID / 版本**：AC-02 / 1.0.0
- **粒度**：原子能力
- **归属注意力**：数据（口径质量）＋ 分析师（去重键与模糊阈值）

---

## 1. 职责

按一份显式的去重规则，在数据集中识别重复记录，移除重复、保留一条**确定性**幸存行，
并保留被移除行的审计（属于哪个重复组、为何被移除）。

**不做**：不校验字段合法性（交 AC-01）、不合并多批（交 AC-04）、不改幸存行的字段值
（`survivor=merge` 的字段合并除外，且需显式开启）。

---

## 2. 输入契约

### 2.1 数据集
标准信封（见规范 §4）。

### 2.2 去重规则 `rules`
```json
{
  "key_fields": ["用于判定重复的字段"],
  "match_mode": "exact | normalized | fuzzy",
  "fuzzy": { "fields": ["参与模糊比对的字段"], "threshold": 0.9, "method": "jaccard|edit" },
  "survivor": {
    "policy": "first | last | max_by | min_by | merge",
    "by_field": "当 policy=max_by/min_by 时的排序字段",
    "merge_fields": ["当 policy=merge 时取非空值合并的字段"]
  }
}
```
- `key_fields` 必须存在于 schema，否则判 `failed`。
- `match_mode=fuzzy` 时 `fuzzy` 必填；阈值 ∈ (0,1]。

---

## 3. 参数 `params`

| 参数 | 取值 | 默认 | 说明 |
|------|------|------|------|
| `normalize` | bool | `true` | `normalized` 模式下的归一化：trim、折叠空白、大小写归一 |
| `keep_removed` | bool | `true` | 是否在输出返回被移除行明细（关闭仅返回计数，省内存） |
| `max_group_size` | int / null | `null` | 单个重复组超过该规模即告警（疑似键选错） |

---

## 4. 输出契约

```json
{
  "deduped_rows": { "schema": [...], "rows": [...], "meta": {...} },
  "removed_rows": { "schema": [...],
                    "rows": [ { "...原字段": "值",
                               "_dup_group": "组id", "_reason": "被哪条幸存行取代" } ] },
  "dup_groups": [
    { "group_id": "", "size": 0, "key": {"字段": "值"}, "survivor_index": 0,
      "match": "exact|normalized|fuzzy", "score": null } ]
}
```
- 每个重复组恰好保留 1 条幸存行；`survivor_index` 指向其在组内位置。
- `fuzzy` 模式下 `score` 记录命中相似度，便于分析师回看阈值是否合理。

**回执 `deltas`**：`{ "input": 行数, "removed": 移除数, "groups": 组数, "max_group": 最大组规模 }`，
`status`：正常 `success`；键缺失/阈值非法 `failed`；触发 `max_group_size` 告警但完成 `partial`。

---

## 5. 错误与边界

| 情况 | 处理 | status |
|------|------|--------|
| `key_fields`/模糊字段不在 schema | 中止 | failed |
| `fuzzy` 阈值越界或 method 不支持 | 中止 | failed |
| `max_by/min_by` 排序字段含空值 | 空值排在末位，不中止 | success/partial |
| 某组规模超 `max_group_size` | 完成但告警 | partial |
| 无重复 | 原样返回，removed 为空 | success |

不负责：合法性校验、跨批次主键重映射。

---

## 6. 幂等与确定性

- `exact`/`normalized`：纯确定性。
- `fuzzy`：比对需定义**稳定遍历顺序**（按 `key_fields` 再按行序），保证同输入同参数同结果；
  实现不得依赖哈希随机序。
- `first`/`last` 的「序」以输入 `rows` 顺序为准，上游若需要稳定序应先排序。

---

## 7. 复用场景

- **CM-01 数据准备组合**第三步（校验之后）。
- 社媒评论 Topic：同一用户重复评论、转发副本去重。
- 人群洞察 Topic：跨渠道同一 ID 合并（`survivor=merge`）。

---

## 8. 验收标准

- [ ] `exact` 下完全相同 key 的行只保留 1 条，移除行带 `_dup_group` 与 `_reason`。
- [ ] `normalized` 下大小写/空白差异被判为重复。
- [ ] `fuzzy` 下相似度≥阈值判重、<阈值保留，`score` 回显。
- [ ] 四种 `survivor` 策略各自选出符合定义的幸存行。
- [ ] 调整输入行顺序（不变 key），`exact` 结果集合不变（幸存行可因 first/last 变化，但去重结果规模一致）。
- [ ] 回执 `deltas.removed` = `removed_rows` 行数。
